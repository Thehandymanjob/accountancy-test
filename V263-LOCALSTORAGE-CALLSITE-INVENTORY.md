## Known architectural blockers

- The accounting `loadDB()` and `persist()` functions are synchronous and must become async, with all callers updated to await completion.
- Projects `prLoad()` / `prPersist()` and Contracts `ctRead()` / `ctWrite()` are synchronous and have broad callers.
- The report module initializes state synchronously at script evaluation (`cfg`, `archive`, `notifications`, `flow`), so it must move behind the IndexedDB bootstrap.
- Language selection currently runs synchronously at the bottom of the document and must be applied after preferences are loaded.
- Existing backup/restore includes LocalStorage and the old test226 IndexedDB database; it must be replaced, not adapted by simply renaming keys.
- Monitor instrumentation currently intercepts all `Storage.prototype.setItem/removeItem` calls; this must be removed, not redirected.

## Acceptance criteria

- Fresh install creates a new, empty `the_handyman_accountancy_v263_idb` database; no legacy values are read or imported.
- All application domains read and write only IndexedDB.
- All save operations wait for transaction completion before reporting success.
- IndexedDB errors fail closed with a clear message; no fallback to LocalStorage.
- Images, logos, receipt attachments and report files round-trip as Blob/File.
- Backups export all app domains and binary values; restore validates and commits transactionally.
- Factory reset backs up and verifies before clearing only the v263 application database.
- No executable file in the release has a LocalStorage, SessionStorage, or Storage.prototype access.
